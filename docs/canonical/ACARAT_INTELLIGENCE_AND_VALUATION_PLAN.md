# Acarat Intelligence and Valuation Plan

**Status:** CANONICAL_PLANNING_CANDIDATE  
**Principle:** estimates are evidence-backed probabilistic decision support, not appraisals and not hidden LLM guesses.

## 1. Intelligence products

Acarat Intelligence must expose separate products for separate markets:

1. Fair Rent — residential and commercial rental range.
2. Fair Sale Value — apartment, villa, floor, duplex, and other supported sale types.
3. Fair Land Value — land-specific value and price-per-square-meter range.
4. Market Range — neighborhood/property-type distribution.
5. Comparable Explorer — the evidence set behind a displayed range.
6. Market Trend — time-adjusted local movement.
7. Listing Premium/Discount — asking price relative to the Acarat evidence range.
8. Investment Scenario — transparent rent/yield/cost assumptions, not investment advice.
9. Listing Performance Intelligence — impressions, engagement, inquiries, viewings, offers, and price-position diagnostics.
10. Customer Match Intelligence — explainable relevance between a customer's requirements and a listing.
11. Renewal/Lifecycle Intelligence — contract-end windows and follow-up prioritization.
12. Data Quality Intelligence — suspicious price, duplicate listing, impossible geometry, stale listing, missing evidence, and inconsistent attributes.

Each product has its own evidence contract and evaluation.

## 2. Official Saudi evidence floor

Acarat should treat official market indicators as evidence inputs and benchmark references, not as a single-property valuation oracle.

Current official research references:

- REGA Real Estate Indicators: https://rei.rega.gov.sa/
- Rental market advanced search: https://rei.rega.gov.sa/en/advanced-search/rental-market
- REGA indicator documentation and methodology pages: https://rega.gov.sa/rega-services/platforms/real-estate-indicators/
- Real Estate Registry: https://www.rer.sa/en
- Ejar integration information: https://www.ejar.sa/ar/page/136435
- National Address developer portal: https://api.address.gov.sa/
- Balady Urban Maps service discovery: https://balady.gov.sa/

Observed official capabilities include sales/rental indicators, neighborhood-level rental ranges for supported areas, documented Ejar transaction statistics, and price indicators with outlier handling. Exact API/data-access rights must be separately contracted or qualified before automated ingestion.

## 3. Evidence hierarchy

Preferred evidence strength:

1. completed, authoritative transaction/contract observations;
2. verified completed Acarat transactions with lawful reuse rights;
3. official aggregate indicators;
4. verified active/expired listing history;
5. broader market listing observations;
6. model-derived features.

Asking prices are not treated as completed market value.

A model trained only on listing ask prices cannot be called the Acarat Fair Price Engine.

## 5. Valuation output contract

Every displayed valuation should contain:

~~~text
ValuationResult
  subject_property_or_land
  valuation_kind
  estimate_low
  estimate_center
  estimate_high
  currency
  unit
  confidence_level
  confidence_score?
  evidence_count
  comparable_set_id
  model_bundle_id
  market_snapshot_id
  as_of
  freshness
  reasons[]
  caveats[]
  abstained
  abstention_reason?
~~~

The UI must not collapse the interval into a single unexplained number.

Example:

> Asking rent: SAR 60,000/year  
> Acarat fair range: SAR 48,000–53,000/year  
> Central estimate: SAR 50,500  
> Ask position: 13.2% above upper fair range; 18.8% above central estimate  
> Confidence: High  
> Evidence: 27 qualifying comparables  
> Updated: 2026-09-xx

Percentages must be computed from the displayed values, never generated by an LLM.

## 6. Comparable selection engine

Comparable selection is a first-class, testable subsystem.

Candidate stages:

1. hard eligibility:
   - same transaction type;
   - compatible property/unit type;
   - valid price/area;
   - acceptable observation age;
   - sufficient location quality;
   - no excluded anomaly flags.

2. geospatial candidate set:
   - same neighborhood when statistically sufficient;
   - PostGIS radius search;
   - H3 parent/neighbor expansion as a derived prefilter;
   - dynamic radius expansion only when evidence is sparse.

3. structural similarity:
   - area;
   - bedrooms;
   - bathrooms;
   - building age;
   - floor;
   - furnishing;
   - parking;
   - elevator;
   - quality/condition;
   - frontage/road data for land;
   - other verified attributes.

4. temporal adjustment:
   - local index/trend adjustment to the valuation date;
   - no adjustment beyond evidence-supported horizons.

5. weight:
   - distance;
   - recency;
   - structural similarity;
   - evidence authority;
   - source quality.

The comparable set is immutable for a given valuation receipt.

## 7. Robust baseline

Before ML, ship and evaluate an explainable statistical baseline.

For each qualified micro-market:

- median;
- weighted median;
- interquartile range;
- 10th/25th/50th/75th/90th percentiles when sample size supports them;
- median absolute deviation;
- robust trimmed means;
- price-per-square-meter distribution;
- observation count;
- effective sample size;
- age/freshness distribution.

This baseline provides a safe fallback and benchmark for all later models.

If ML cannot materially improve the held-out benchmark with calibrated uncertainty, keep the simpler baseline.

## 8. Model architecture

Preferred model family is a benchmarked ensemble.

### 8.1 Component A — comparable estimator

Weighted comparable model produces a transparent estimate and interval.

### 8.2 Component B — hedonic/tabular model

Benchmark candidates include:

- CatBoost;
- LightGBM;
- quantile regression forests;
- generalized additive/hedonic models.

Selection is evidence-based, not based on popularity.

The model should support quantile outputs or another calibrated interval method.

### 8.3 Component C — spatial residual model

A spatial correction can model residual neighborhood/micro-market effects using:

- H3 cells;
- spatial smoothing;
- hierarchical location effects;
- graph/adjacency features;
- distance-to-POI and accessibility features.

No protected/sensitive personal characteristic is permitted as a ranking or valuation feature.

### 8.4 Component D — temporal market adjustment

Use local time-series/indicator effects to normalize historical comparables to the valuation date.

### 8.5 Ensemble

The final result may blend components based on evidence density.

Example policy:

- dense evidence: comparable + tabular + spatial + temporal;
- moderate evidence: comparable + tabular + broad-area trend;
- sparse evidence: robust broad-area range with low confidence;
- insufficient evidence: abstain.

## 13. Confidence

Confidence should be computed from evidence, not language-model self-confidence.

Candidate factors:

- number of qualifying observations;
- effective sample size after weights;
- distance distribution;
- recency;
- feature completeness;
- model calibration;
- agreement among ensemble components;
- out-of-distribution score;
- neighborhood coverage;
- property-type coverage.

Confidence labels can be:

- HIGH;
- MEDIUM;
- LOW;
- INSUFFICIENT_EVIDENCE.

Thresholds are versioned and tested.

## 14. Calibration

Required interval evaluation:

- empirical coverage of 50/80/90/95% intervals;
- interval width;
- coverage by city;
- coverage by property type;
- coverage by price band;
- coverage by low/high evidence density;
- rental versus sale versus land;
- temporal drift.

A narrow but under-covering interval is a failure.

## 15. Accuracy evaluation

Do not optimize a single average error.

Required metrics include:

- MAE;
- median absolute error;
- MAPE/SMAPE where denominator behavior is safe;
- RMSLE when justified;
- percentage within ±5%, ±10%, ±20%;
- quantile/pinball loss;
- calibration coverage;
- interval width;
- rank/order quality for candidate comparisons.

Report segment performance.

## 16. Leakage prevention

Strictly separate:

- transaction outcome features;
- post-listing engagement;
- future market indicators;
- contract completion status;
- user behavior after the valuation timestamp.

Training features must be valid as of the prediction timestamp.

## 17. Data split strategy

Random row split alone is forbidden for primary evaluation.

Use:

- time-based holdout;
- geographic holdout;
- property-identity grouping;
- source-aware grouping;
- duplicate prevention;
- optional city transfer benchmark.

The model must prove performance on newer unseen transactions, not memorize historical property records.

## 18. Explainability

Every valuation explanation is built from computed factors.

Candidate explanation:

- "Comparable apartments in this neighborhood and size band cluster around SAR 49k–52k/year."
- "This unit has parking and is 14% larger than the median comparable."
- "The local rent index increased 3.1% over the evidence period."
- "The asking price is above the 90th percentile of the selected comparable set."

The LLM may convert structured explanation facts into user-friendly Arabic/English, but cannot invent factors.

## 25. Drift monitoring

Monitor:

- feature drift;
- residual drift;
- interval under-coverage;
- city/type errors;
- market regime changes;
- source coverage changes;
- stale official indicators;
- sudden listing-price manipulation.

Model output can automatically downgrade confidence without automatically retraining/deploying a model.

## 26. LLM boundary

The LLM may:

- parse user intent;
- explain a valuation receipt;
- summarize comparable facts;
- answer grounded questions;
- produce scenario narratives.

The LLM may not:

- invent transaction data;
- alter the numeric valuation;
- hide low confidence;
- convert an abstention into an estimate;
- recommend a property based on sensitive personal attributes;
- produce an appraisal/legal guarantee.

## 27. Initial implementation order

1. source/evidence contracts;
2. robust neighborhood/property-type aggregates;
3. comparable engine;
4. deterministic market-position card;
5. held-out benchmark corpus;
6. quantile/hedonic model benchmark;
7. calibrated ensemble if proven;
8. land-specific model;
9. neighborhood intelligence;
10. listing diagnostics;
11. customer matching;
12. lifecycle forecasting.

Acarat can deliver substantial value before the first production ML model.
